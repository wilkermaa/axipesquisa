# Licença: decisão expressa do titular necessária

**Esta entrega NÃO concede licença.** Estar disponível em GitHub não torna o projeto automaticamente open source. A análise jurídica depende da titularidade do conteúdo e de eventuais colaboradores ou materiais de terceiros.

| Opção | Reutilização | Atribuição | Consequência |
|---|---|---|---|
| MIT (código e documentação original) | Comercial e modificação permitidas | Preservar aviso de copyright e licença | Mais simples; não assegura nome no resultado gerado pela IA |
| Apache-2.0 (código e documentação original) | Comercial e modificação permitidas | Preservar avisos; registrar alterações | Concessão expressa de patentes e texto mais longo |
| MIT (scripts) + CC BY 4.0 (textos e materiais autorais) | Comercial e modificação permitidas | Créditos e indicação de alterações para textos | Distingue software de conteúdo editorial, mas exige marcações claras |
| Sem licença por enquanto | Consulta pública do código no GitHub conforme seus termos | Direitos autorais preservados | Não é open source para reutilização geral |

**Recomendação para avaliação:** MIT para scripts e CC BY 4.0 para textos **se** a intenção for adoção ampla com atribuição. Uma alternativa administrativamente mais simples é MIT para todo o código e documentação do repositório, exceto materiais de terceiros. Ambas permitem uso comercial; se isso for indesejado, o projeto não será uma licença open source tradicional.

A assinatura `◌ AXI · nome/e-mail do usuário` identifica a resposta de quem usa a skill; **não garante crédito obrigatório ao autor do método**. Copyright, reconhecimento acadêmico, atribuição em derivados e marca são assuntos diferentes.

Antes de publicar, titular deve escolher a alternativa, declarar como quer constar publicamente e confirmar direitos sobre os materiais incluídos. Só então gerar `LICENSE` com texto canônico verificado, declaração de escopo em `README.md` e aviso de autoria em `NOTICE`, se adequado.
