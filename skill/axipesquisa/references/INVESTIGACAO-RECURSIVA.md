# Investigação recursiva do todo e das partes — AXI v2.4.1

**Regra metodológica:** cada parte relevante pode tornar-se um **novo todo** e abrir outro ciclo A → X → I. Toda descoberta precisa retornar ao **todo-pai** para adquirir significado. O todo assim enriquecido deve devolver sua compreensão atualizada às partes relacionadas. É uma estrutura de investigação recursiva e relacional, não mera lista encadeada linear.

## Oito movimentos

| Fase | Movimento | Objetivo |
|---|---|---|
| A — Análise | 1. Identificar o todo | Objeto, finalidade, contexto, fronteiras |
| A — Análise | 2. Identificar as partes | Componentes relevantes |
| A — Análise | 3. Identificar a função do todo | Papel e funcionamento, quando aplicáveis |
| A — Análise | 4. Identificar a função de cada parte | Contribuições, relações e dependências |
| X — eXpansão | 5. Expandir o todo | Contextos, conexões, comparações úteis |
| X — eXpansão | 6. Expandir cada parte | Investigar subpartes e iniciar novos ciclos relevantes |
| I — Integração | 7. Integrar o todo | Síntese ascendente: partes → todo |
| I — Integração | 8. Integrar cada parte | Revisão descendente: todo → partes |

## Recursão seletiva e integração em duas direções

1. Delimitar o todo, suas partes, funções e limites, distinguindo evidências de hipóteses.
2. Expandir o todo no contexto pertinente e expandir cada parte relevante. Uma parte se transforma em novo todo **somente se houver ganho útil para a investigação**; nesse caso, repetir A → X → I, preservando o identificador e o contexto do todo-pai.
3. **Integração ascendente (partes → todo):** devolver os achados, fontes, dependências e limites ao conjunto, reconstruindo compreensão e eventuais propriedades emergentes.
4. **Integração descendente (todo → partes):** revisar como essa compreensão altera ou esclarece as partes, inclusive aquelas que não foram diretamente aprofundadas.
5. **Critério de parada:** não abrir níveis adicionais se forem irrelevantes, redundantes ou especulativos. A profundidade é proporcional ao objetivo; não impor oito seções visíveis numa pergunta simples.

## Estrutura dos vínculos e visualização

Uma **árvore** é adequada para todo → partes → subpartes. Quando há relações cruzadas ou múltiplos pais, representar também um **grafo**, sem forçar essas ligações em hierarquia falsa. A lista encadeada descreve apenas a continuidade das descobertas, não a estrutura completa do conhecimento.

**Padrão visual preservado da v2.4.0:** na Análise, se houver hierarquia fiel, priorizar Markmap Tree + Cards, ou figura renderizada equivalente, com aviso de entrega parcial quando inviável. A fase Integração mantém a obrigação separada de imagem de fluxograma visível **somente quando houver fluxo real fielmente representável**. Nem a árvore nem a recursão justificam inventar processos, causas, normas ou relações. Preservar fontes ABNT, leitura integral, privacidade e protocolo jurídico.

**Histórico preservado:** a referência `METODO-AXI.md` da linha congelada permanece byte a byte inalterada; este documento a complementa, sem sobrescrever os benchmarks C0/C1/C2 originais.
